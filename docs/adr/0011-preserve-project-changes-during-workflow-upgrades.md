# 升级工作流时保留项目修改

Installed Workflow（已安装工作流）由项目拥有，安装后的 runner、触发条件和 Prompt 等修改不能在版本升级时被整体覆盖。当前 `init` 只负责首次安装，`migrate` 只识别固定来源的旧 Loop Engineering 安装；二者均不提供 Graph Engineering 已安装版本之间的升级路径。

增加独立 `upgrade` 入口，以旧版本原始模板、项目当前文件和目标版本模板做三方合并：未修改文件应用新版内容，互不冲突的项目修改保留；存在冲突时展示计划并停止，处理后再应用。保留 `migrate` 的旧产品迁移职责，不通过删除已安装文件再执行 `init` 实现升级。该选择要求维护可核对的旧版本基线与冲突处理能力，以换取项目修改在持续升级时得到保留。

旧版基线来自安装记录指向的准确版本 npm 包，并核对包来源提交及文件清单；允许提供本地包供离线使用，不能核对时停止。目标版本默认取执行命令的 CLI 版本，也可通过 `--to` 指定已发布版本，因此新版 CLI 可以将项目从 0.3.1 升级到已发布的 0.3.2，而不要求旧版本自身拥有升级命令。

默认只展示计划与 diff，显式 `--apply` 才应用整套无冲突计划。普通写入失败恢复原文件，全部成功后才更新安装记录；应用前复核文件没有再次变化。首次支持 0.3.1 起的当前 schema 安装，同版本不执行升级，降级与旧 schema 暂不支持。

本 ADR 记录已确认方向，不表示升级命令已经实现。可执行规格见 [Workflow 版本升级设计](../design/workflow-upgrades.md)；历史 npm 包和 Release 不回写。
