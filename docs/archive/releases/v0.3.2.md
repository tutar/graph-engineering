# Graph Engineering v0.3.2

Graph Engineering `v0.3.2` 与 `@tutar/graph-engineering@0.3.2` 交付更新后的 Coding 和 Development Workflow，以及整套 Workflow 安装 CLI。GitHub Release 的 `.tgz` 附件与 npm 包具有相同的包校验值。基于 [PR #104](https://github.com/tutar/graph-engineering/pull/104)。

## Highlights

- Coding Task 的 Work Goal 显式引用 `$skill-name` 时，Action 在创建 Goal 前从当前 Skill catalog 解析 enabled Skill，要求 Agent 读取并遵循它。缺失、disabled、同名歧义或 catalog 不一致时停止；这仍是兼容桥接，不宣称 Codex 原生 structured Skill invocation。
- Coding Goal Action 仅要求稳定 Codex CLI 不低于 `0.153.4`，复用 runner 上已安装的兼容版本；无兼容版本时按最低版本安装。
- Development Workflow 改用本仓库维护的本地 Action；其 Task Invocation 与 Session 恢复 bundle 保持原固定提交内容，运行时选择改为复用符合最低版本的 runner CLI。持久 task state 保存在 checkout 外。
- Goal 终止与最终 Turn 持久化之间的竞态已修复，避免漏掉最终 Agent 消息。

## Install

在目标 Git 仓库根目录执行：

```bash
npx --yes @tutar/graph-engineering@0.3.2 init --dry-run
npx --yes @tutar/graph-engineering@0.3.2 init
npx --yes @tutar/graph-engineering@0.3.2 check
```

已安装的整套 Workflow 由项目所有；`init` 不覆盖现有文件。更新前请先检查本地修改，并按 CLI 文档处理目标冲突。`check` 的静态文件匹配不证明 runner、认证或实际任务执行已经验收。

## Verification boundary

Workflow 测试 70/70、CLI 测试 13/13、Development Action Task Invocation 集成测试 27/27。隔离的真实 Codex CLI `0.156.1` 场景验证了 Coding Skill 桥接，以及 Development Action 对已安装新版 CLI 的复用和一次真实执行。原始“升级后 Workflow 报错”的失败步骤、错误及当时版本没有日志可核对；这些验证不能反推原故障根因。详见 [Issue #102](https://github.com/tutar/graph-engineering/issues/102) 与 [Issue #103](https://github.com/tutar/graph-engineering/issues/103)。
